## 3. Gaps needing a founder decision

> **[CMO triage 2026-07-15]** Each gap tagged **DO-NOW** (fix before the keychain/gels MOF pack trafficks — cheap, or a live leak/liability), **DROP-002** (hard dependency on drop-002 day; build in that sprint), or **LATER** (roadmap, no current ad-sync leak). Summary: DO-NOW = G1, G4-decision, G5. DROP-002 = G3, G6, G7 (+ G4 implementation). LATER = G2 (for ad-sync; but it's a BUILD-NOW *capture* priority per `Marketing/Strategy/funnel-teardown-2026-07.md` #1 — flagged, not deferred by marketing).

- **G1 — no SMS-first module on `/lp/pour`. → DO-NOW.** `SHR_MOF_ALL_VID_07` routes to "/lp/pour SMS-first module", but every LP collects email first, phone second (DropAccessForm). The audience is *already on the waitlist*, so the email step is dead weight for them. This is a live message-match leak the moment VID_07 trafficks. Cheapest fix: re-point the ad's CTA copy to the existing phone step, or ship a phone-first variant (`/lp/pour?sms=1`) that skips straight to DropAccessForm's phone step. Do before this ad goes live; no drop-002 dependency.
- **G2 — no quiz page. → LATER (ad-sync) / BUILD-NOW (capture).** P2 ("find your pour" quiz keychain draw, 100/drop) is referenced in the promo plan, but `app/` has no `/quiz` route. No ads point there, so for *this doc* (ad↔LP sync) it's not a traffic leak. But it is the single highest-leverage capture gap in the funnel (`funnel-teardown` upgrade #1; FLOW C and flavor-segmented drop creative both depend on it). Not deferred by marketing — flagged as a build priority owned by the growth/eng track. When it ships, wire it as the post-signup step on all 5 LPs.
- **G3 — no landing surface for the keychain anchor drop itself. → DROP-002.** The one-time 100-unit $15 authenticated drop on drop-002 day has no PDP/section anywhere in `app/`. Hard dependency: the anchor is what makes "$15 value" a legally-real claim, so `/drop` (or the draft product `gid://…/10300264677652`) needs an authenticated-drop module live *on drop-002 day*. Ops must confirm 100-unit sell-through before any `-PA` "$15 value" re-cut trafficks. Build in the drop-002 sprint alongside G7.
- **G4 — referral ladder economics. → DECISION DO-NOW / implementation DROP-002.** Ads promise items at 3/5; committed public copy promised credits at 3/5. Interim fix keeps **both** on `/refer` (credits + keychain at 3, credits + gels at 5 → +$1.50/+$3.25 COGS per milestone on top of credits). That double-pays each milestone — safe on the 30% cap (a $0 gift is COGS, not discount) but leaky on contribution. Get the CFO sign-off on the P3/P4 items-*replace*-credits swap (`discount-matrix.md` §4) NOW so post-launch cohorts stop paying twice; the `/refer` copy shrink to items-only is a small edit that lands with the drop-002 program. Founders keep committed credits either way.
- **G5 — `/refer` has no paid-UTM instrumentation. → DO-NOW.** Keychain cuts route referral intent there via the end-card chip, but signups log as generic `refer_page` — per-ad referral-start attribution (the *primary* metric for `RIT_SPK_04`/`FCS_IMG_02`, per the KPI framework) isn't measurable. This is a measurement blind spot on the exact ads whose job is referral starts. Fix: `utm_content` passthrough on the chip link (preserve the existing `event_label: refer_page` gtag; add `utm_content={ad_code}` so referral-start can be attributed per ad). Cheap; do before the keychain six trafficks.
- **G6 — gels copy blockers unchanged. → DROP-002 (blocked on ops data).** `[PAIRS_OR_SINGLES]` + INCI verification still gate any "6 uses"/ingredient gels copy (pack §0.4, promo plan §6). Not a marketing decision — the gate is the gels PO + INCI (`promo-value-add-plan.md` §6). The $18 SKU decision legalizes "$18 value" but does NOT unblock uses/ingredient copy. Hold that copy until the first gels PO lands; the "$18 value" gift language ships without it.
- **G7 — ops config for the anchor drop. → DROP-002.** §0.6 assumes "100 / $15 / drop-002 day" will exist in ops config like drop counts do; `app/lib/drop-config.ts` has no keychain-anchor fields yet. Engineering dependency for G3 (the anchor line/value badge must read from config, per the honesty rule, never hardcoded copy). Spec now, ship in the drop-002 sprint.
